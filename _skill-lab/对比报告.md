# 三类 AI 短剧 Skill 横向评测报告

> 日期：2026-11-05
> 输入：原著第 1–3 章 / EP01 剧本（按各组 skill 的实际入口）
> 规格：60–90 秒、9:16、冷调宅斗、目标模型 MiniMax H3
> 约束：三组均禁止参考项目已有的 EP01 制作包，避免抄答案；均未调用付费 API。

## 一、总分

| 维度（各 5 分） | A drama-skills | B take | C storyboard-skill |
|---|---|---|---|
| 1 忠实度 | 5 | 4 | 4 |
| 2 结构完整度 | 5 | 3 | 3 |
| 3 分镜可执行性 | 5 | 3 | 4 |
| 4 一致性机制 | 5 | 1 | 2 |
| 5 H3 适配度 | 5 | 1 | 1 |
| 6 可验证性 | 4 | 3 | 2 |
| **合计** | **29 / 30** | **15 / 30** | **16 / 30** |

结论：**A 完胜，且不是小幅领先。** 差距主要集中在第 4、5 两项——恰好是短剧能不能落地的那两项。

## 二、A：zenstory-ai/drama-skills（29 分）

产物 11 份、1346 行、约 2.1 万中文字：

```
short-drama.json                项目档案（H3 方言、节奏、语速）
创作者决策/production-profile.jsonl
项目开发/creative-brief.md        创作命题
项目开发/story-engine.md          故事引擎
项目开发/episode-map.jsonl        4 集地图
项目开发/adaptation-map.jsonl     12 条改编处置（preserve/compress/omit...）
剧集/EP001/剧本.md                3 场、88 秒
剧集/EP001/视觉设定.md            3 人物、2 造型、1 地点、2 道具、5 条连续性锁
剧集/EP001/分镜.md                18 镜、88 秒、平均 4.9 秒
剧集/EP001/图片提示词.md          8 块资产板
剧集/EP001/视频提示词.md          18 条 full-reference 六段式
```

**最强的地方（别的两家完全没有）：**

1. **连续性锁是字符串级的**。`LOCK-SUINING-DRESS` 的锁面 `moon-white cross-collar ruqun under a pale blue-grey bijia` 必须逐字出现在对应资产板、关键帧提示词、MOTION 正文里。跨镜服装漂移从"靠眼睛看"变成"可机械比对"。
2. **H3 方言是判定表，不是形容词**。按"用途 + 是否挂参考图"自动决定走 T2VA / I2VA / FL2VA / Ref2VA，`<Picture N>` 编号必须等于挂图顺序，时长 4–15 秒整数，对白按 4.1 字/秒预算。
3. **说话人绑定**。每条 MOTION 明写谁说话、画里另一人"嘴唇闭合、不说话"，并要求声音分层（`overall_soundscape` / `non_diegetic_music` 显式写 `N/A`）。
4. **场景站位与轴线**。分镜前先锁定床/窗/门方位、人物朝向社会轴线，后面的 18 镜全部引用。

**弱的地方：**

- 入口依赖 Python。`project_tool.py init` 是 Quick Start 第一条，本机 Python 是商店存根，只能手工建目录；发布/接受记录、时长估算、检查器全部跑不了。
- 默认镜长 `2.5s` 与 H3 的 4 秒下限冲突，只有主动跑 `status` 才会提示。
- `REF` / `PLAN` / 待补 / 文生视频 四态靠语义区分，新手容易全部写成"无"。

## 三、B：XucroYuri/take（15 分）

产物：script.md / shots.json（26 镜、88s）/ storyboard.md / validate 输出。

**强项：**

- 校验是真的能跑：zod schema + index 连续性 + 悬空 beatId，4 条命令全部 exit 0，报错能定位到字段路径。
- 文件即项目，`export storyboard` 一条命令出人类可读稿。

**致命伤：**

- **H3 只是路由壳**。`adapters/minimax.ts` 仅 25 行，继承通用 OpenAI 兼容适配器。CLI 的 `generateVideos` 固定走 Seedance，配置里的 H3 根本不被读取；实测 H3 排第一仍报 seedance 缺 key。
- **参数全丢**。生成请求只传 `{ prompt }`，时长、9:16、首帧图、分辨率都不进请求；图像默认 1536×1024 横屏。
- **没有声音层**。schema 里没有台词/VO/字幕/音效/音乐字段，20 条台词只能塞进 summary 自由文本。
- `characterRefs` 不被消费，没有参考图/seed/multi-reference。

一句话：**它是"画面素材清单"工具，不是"短剧时间线"工具。**

## 四、C：ai-video-storyboard-skill（16 分）

产物：单份 storyboard.md（402 行，20 镜，88.0s 精确对齐）。

**强项：**

- 分镜表本身好用：时间码、叙事功能、景别机位、运镜、一句话画面、台词五件套齐全。
- "Visual Theme 每镜复述"确实能让 20 条提示词在色彩/光比上统一。

**致命伤：**

- SKILL.md 引用的 `references/shot-types.md`、`camera-moves.md`、`lighting.md`、`genre-templates.md` 四份文件**仓库里根本不存在**，README 的安装命令会直接失败。
- 提示词是英文自由散文，`cinematic 1080p` 收尾——H3 原生 768p、24fps，没有 1080p 这一档。20/20 条要重写。
- 台词全放在中文音频段，prompt 里一个字没有，浪费 H3 的原生中文对白与唇形。
- 一致性只有"重复形容词"，没有资产、参考图、首尾帧、seed。

一句话：**好模板，不是生产方案。**

## 五、对《梨花误》的直接价值

最有价值的不是"选一个装"，而是把 A 的机制拿过来用：

| 现有 EP01 做法 | A 组暴露的问题 | 建议 |
|---|---|---|
| 26 镜，含 2s/3s | H3 最短 4s，26×4=104s > 88s | 合并到 18–20 镜，A 组已验证 18 镜 88s 可行 |
| 提示词四段式 + 后缀 | H3 要六段式 + Subject 标签 + 保留标记 | 改用 full-reference 六段 |
| 台词只在制作包里 | H3 原生音频，台词必须进 `<d>[Chinese]` | 每条 MOTION 写说话人 ID 与闭嘴指令 |
| 角色靠 prompt 形容词 | 无跨镜硬约束 | 建连续性锁，锁面逐字复用 |
| 全局负面词 | H3 对否定句不敏感（实测） | 关键约束写正面描述，不靠负面词 |

## 六、推荐落地方式

**不建议自建全套 12 个 skill**——A 是从 1000+ 真实项目蒸馏的，自建不可能超过它。

推荐：

1. 把 drama-skills 作为主干引擎，正式装进项目；
2. 只自建一个薄层：`梨花误-qc`，补三件事：
   - 结构断言（Node 实现，绕开 Python 依赖）：时长合计、锁面逐字出现、`<Picture N>` 与挂图顺序一致、4–15s 边界、台词字速预算；
   - 视觉评审（把关键帧喂回来按固定清单打分）；
   - 回归基线（EP01 的 18 镜作为 golden test）。
3. 把《梨花误》私有规则（五律、三问、色彩弧线、EP01 视觉圣经）写成项目档案，而不是改 skill 源码。

这样维护成本最低，且换模型时只改档案里的方言文件。
