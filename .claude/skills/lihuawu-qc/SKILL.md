# 梨花误 · 制片质检

对 drama-skills 的产出做**确定性校验**。只回报事实，不打创作分。

## 什么时候用

- 写完或改完 `分镜.md`、`视频提示词.md`、`视觉设定.md` 之后；
- 换视频模型、改集长、合并镜头之后；
- 生成关键帧之前，确认提示词没有结构性错误；
- 用户问「这集能不能开做」。

## 怎么跑

```bash
node .claude/skills/lihuawu-qc/scripts/qc.mjs "短剧项目/制片"
node .claude/skills/lihuawu-qc/scripts/qc.mjs "短剧项目/制片" "剧集/EP001"
node .claude/skills/lihuawu-qc/scripts/qc.mjs "短剧项目/制片" --json
```

退出码 0 = 全部通过，1 = 有失败项，2 = 文件缺失。

## 检查项

| 编号 | 断言 | 失败含义 |
|---|---|---|
| S1/S2 | 分镜与视频提示词存在 | 阶段没做完 |
| S3 | SHOT 与 MOTION 数量一致 | 有镜头没写提示词，或反之 |
| S4 | 单镜 4–15 秒整数 | 低于 H3 下限，生成会失败或被拉长 |
| S5 | 总时长 60–90 秒 | 集长不达标 |
| S6 | MOTION 引用的 SHOT 存在 | 悬空引用 |
| S7 | H3 六段结构齐全 | 提示词不是 full-reference 格式 |
| S8 | `<Picture N>` 不超过挂图顺序 | 标签指向不存在的图 |
| S9 | 中文对白 ≤ 4.5 字/秒 | 台词会被赶词或截断 |
| S10 | 无 1080p / 30fps | 抄了错误规格 |
| S11 | 连续性锁面逐字出现 | 跨镜造型会漂移 |

## 怎么读结果

- 每条失败都带镜号，直接定位到 `分镜.md` 或 `视频提示词.md` 的对应小节；
- S4 失败通常是分镜阶段的问题，不要靠改提示词绕过；
- S9 失败优先删字或加时长，不要加快语速；
- S11 失败说明锁面被改写或漏写，回到 `视觉设定.md` 复制原文。

## 不做的事

- 不判断剧情好不好、镜头美不美；
- 不生成、不改写任何文档；
- 不替代 `short-drama-review`（那是创作审查）。

## 视觉评审（需要人或多模态模型）

结构通过不等于画面可用。关键帧出来后另做一轮，按固定清单逐项打分：

1. 是否同一张脸（对照角色板）
2. 是否同一套服装（对照锁面）
3. 景别是否与分镜一致
4. 光线方向是否与场景站位一致
5. 有无文字、畸形手、多余人物
6. 道具状态是否正确（梨花的四个状态最容易错）

每项 0–5 分，低于 3 分即返工，并在 `视觉评审.md` 记录镜号与原因。
